## Purpose

Govern agent behavior evolution as an institutional change process.

Sentinel separates:

1. experience evidence;
2. persistent knowledge and provenance;
3. executable skill versions;
4. validation;
5. independent approval;
6. controlled deployment;
7. post deployment monitoring;
8. suspension, rollback and retirement.

This follows the core WikiSkill pattern of compiling experience into persistent knowledge and then into reusable skills, while applying Sentinel's institutional authorization, audit and evidence controls.

## Lifecycle

`draft -> proposed -> validating -> ready_for_approval -> approved -> active -> suspended -> retired`

A failed validation returns the proposal to a non deployable state.

## Enforcement rules

- Atomic domain and audit writes use Sentinel's Version 30 `auditedBatch` path so governed state changes and their audit event commit together.
- Skill scope cannot exceed the parent AI agent's approved tools or data.
- Parent agent membership and lifecycle are rechecked at deployment.
- Candidate content is SHA 256 digested.
- Validation binds to the candidate digest.
- Content digest mismatch blocks deployment.
- Validation must pass safety, policy, tool scope and data scope checks.
- The proposer cannot approve the proposal.
- An approver can decide a proposal only once.
- High and Critical skills require two independent approvals.
- Low and Medium skills require one independent approval.
- Deployment requires the exact validated and approved digest.
- Suspended or retired parent agents cannot receive a skill deployment.
- Material performance regression or safety breach suspends both the skill and active deployment.
- Rollback can target only a previously validated, approved and actually deployed version.
- Active skills must be suspended before retirement.
- Skill evidence export includes audit integrity.
- System Evidence Export 2.0 includes the complete linked skill governance record.
